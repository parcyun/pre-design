# pre-design

Codex가 프로젝트·디자인·톤·오브젝트를 만들기 전에 방향과 완료 기준을 실용적으로 고정하는 사전 설계 스킬이다.

> 질문을 많이 하는 스킬이 아니라, 잘못 결정하면 되돌리기 비싼 부분만 먼저 잠그는 스킬.

## 적용 범위

- 새 프로젝트나 제품의 첫 시각 설계
- 기존 프로젝트의 첫 디자인 패스
- 리디자인, 리브랜딩, 톤 재설정
- 새 페이지 유형, 캠페인, 템플릿, 디자인 시스템
- 히어로, 내비게이션, 카드군, 차트, 슬라이드, 포스터, 썸네일 같은 주요 오브젝트

이미 확정된 시스템 안의 작은 오브젝트는 프로젝트 전체를 다시 논의하지 않는다. 그 오브젝트의 역할·내용·상태·크기·상호작용만 정한다.

## 무엇이 실제로 강화됐나

기존 버전은 모든 작업에 비슷한 질문과 절차를 적용해, 맥락이 충분한 요청에서도 느리고 결과 차이가 잘 보이지 않았다. 현재 버전은 다음처럼 바뀌었다.

- **Codex 네이티브 조사:** 대화, 프로젝트 파일, 스타일, 에셋, 기록을 먼저 읽는다.
- **적응형 실행:** 바로 진행 / 안전한 가정 / 결과를 바꾸는 질문 1개 중 하나를 선택한다.
- **4개 작업 범위:** 프로젝트 시작, 디자인 시작, 톤 재설정, 오브젝트 사전 작업을 구분한다.
- **기존 시스템 보존:** 유지할 것과 바꿀 것을 분리해 불필요한 재설계를 막는다.
- **구현 가능한 handoff:** 의도, 유지·변경 범위, 콘텐츠, 상태, 제약, 검증 기준을 남긴다.
- **실용 검증:** 점수 대신 실제 UI·렌더·출력물에서 통과 여부를 확인한다.
- **콘텐츠 극단값:** 긴 문구, 빈 상태, 오류 상태, 로딩 상태까지 필요 범위에서 검증한다.
- **명확한 완료 상태:** 구현, 정적 검증, 실제 경험 검증, 미검증을 구분한다.

## 실행 흐름

```text
대화·파일·기존 시스템 확인
          ↓
프로젝트 / 디자인 / 톤 / 오브젝트 범위 선택
          ↓
최소 brief + 유지·변경·금지·미정 항목 정리
          ↓
브랜드 또는 하나의 시각 방향 고정
          ↓
구현용 handoff 작성 → 실제 제작
          ↓
실제 UI·렌더·출력 환경에서 검증
```

## Codex에서 사용

Codex는 시각적 방향이 새로 필요하거나 잘못된 방향의 재작업 위험이 있는 요청에서 이 스킬을 자동으로 선택할 수 있다.

명시적으로 호출하려면:

```text
$pre-design으로 이 프로젝트의 첫 디자인 방향부터 잡아줘.
$pre-design으로 기존 화면의 톤을 새로 정의하고 리디자인해줘.
$pre-design으로 이 카드 컴포넌트의 역할과 상태를 먼저 설계해줘.
```

고정된 색상 교체, 오탈자 수정, 정해진 크기의 단순 export처럼 방향이 이미 확정된 기계적 수정에는 전체 discovery를 실행하지 않는다.

## 검증 구조

모든 결과물은 목적, 계층, 일관성, 콘텐츠, 기능, 실제 사용 환경, 절제를 확인한다. 작업 범위에 따라 다음을 추가한다.

- 프로젝트: 대표 사용자 경로와 시스템 일관성
- 디자인: 대표 화면과 반응형/출력 크기
- 톤 재설정: before/after 변화와 보존 대상
- 오브젝트: 상태, 변형, 내용 길이, 로딩·빈 상태·오류

검증 결과는 `implemented locally`, `validated`, `verified in real UI`, `not verified`로 구분한다.

## 다른 스킬과의 관계

- `pre-design`: 구현 전 목표·범위·방향·검증 기준 확정
- 브랜드 스킬: 고유 색상·타이포그래피·컴포넌트 규칙 적용
- `authentic-web-design`: 실제 웹 UI에서 AI-generated 패턴 제거
- 포맷 스킬: 웹, 프레젠테이션, 문서 등 결과물별 제작과 검증

세부 실행 규칙은 [`SKILL.md`](./SKILL.md)에 있다.
